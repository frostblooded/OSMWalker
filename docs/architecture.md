# Architecture map

Where things live, and the links between files that no import shows. Every
source file opens with a comment saying what it does; read that before the
code.

## Layers

Imports only point down this list (`src/sw/` imports nothing).

| Layer | Folder | What it holds |
| --- | --- | --- |
| Screens | `src/ui/` | Preact screens and sheets. `kit.tsx` + `app.css` are the UI kit (see `docs/ui-guidelines.md`). `help.ts` fills Help text with numbers from `src/core` (and `snap.ts`); `HelpSheet.tsx` loads it as its own chunk, off the startup path, and the text when Help first opens. |
| App | `src/app/` | `loop.ts` ticks the game while the page is visible; `idle.ts` yields and waits for idle time. |
| Map | `src/map/` | `scene.ts` decides what the map shows and where the camera points. `mapView.ts` is the only file that talks to MapLibre. |
| Game | `src/game/` | `game.ts` runs a city: walker, streets, rewards and saves. `saveFile.ts` saves and settings, `hud.ts` what the screens show. |
| Streets | `src/streets/` | The Web Worker that fetches, decodes and caches street tiles (`source.ts`), and `loader.ts`, which picks which tiles to load next. |
| Network | `src/net/api.ts` | The game's outside services: OpenFreeMap street tiles, Overpass, Photon and Nominatim search, and the city outline. The map style and map tiles are fetched by `src/map/mapView.ts` and MapLibre itself. |
| Core | `src/core/` | Pure logic with no DOM and no network: the walker (`walker.ts`: he wanders at random with no goal), route (A*), food orders, their pay and the wait for the next one (`orders.ts`), the upgrades and their prices (`upgrades.ts`), his money, deliveries, upgrades and places visited (`stats.ts`), history and his trail, his look on the map (`look.ts`), the debug log and problems, money in cents, a seedable RNG, and the street graph and tile decoding. |
| Offline | `src/sw/` | The service worker and its cache rules, built on its own. |

## Hidden links

- **Help text.** `public/data/help.txt` holds `{PLACEHOLDERS}`, and `src/ui/help.ts` fills them from core constants (the food kinds from `orders.ts` `FOOD`, the upgrade list from `upgrades.ts` `UPGRADES`). `vite.config.ts` hashes the file into `__HELP_VERSION__`, which goes in its address (`HelpSheet.tsx` `HELP_URL`), so a deploy that changes Help gives it a new address. The service worker serves a `data/` file with `?v=` cache-first and deletes its older versions when it stores a new one (`src/sw/strategy.ts` `replaced`). `tests/unit/help.test.ts` fails on a missing or unused value, or a screen button with no page.
- **Orders and pay.** With no goal the walker calls `events.idle` and wanders (`Walker.wander`); `Game.step` counts `Job.waitLeftS` down while he moves and then calls `Game.newOrder`, which takes food places and doors from the graph (`placesIn`, `homesIn`; street corners stand in where there are no house numbers) and asks `makeOrder` for one. The pay is fixed then (`payOf`, the drop in `ROUTE_FACTOR` times the straight line) and paid at the door (`Game.onArrived`). `events.idle` while on an order means he gave up on it, so it is cancelled. The map's 1 and 2 pins come from `MapPort.setStops`. Doors are the tiles' `housenumber` layer (`core/ofm.ts` `homes`), which has no street name, so the street is taken from the nearest corner (`StreetGraph.streetAt`) when the order comes.
- **Upgrades and the economy.** `upgrades.ts` `UPGRADES` holds each upgrade's first price and what it opens after; `speedX` and `waitX` turn what he owns into his speed (`Game.equip`) and the order wait (`waitS`). Help's upgrade list and numbers come from there (`help.ts` `upgrades`). Any change to pay, waits, prices or speeds goes through `npm run sim` (`tests/support/economy.ts`, the real `makeOrder`, `waitS` and `Stats` in a made-up city), and `tests/unit/economy.test.ts` keeps the targets.
- **Saves.** Changing a saved field means a repair step on the way in from `src/game/saveFile.ts`, because players keep old saves. The order he is on and the wait for the next one are saved as `job` (`Job.fromJSON`; a save without it starts with no order and a full wait). Upgrade counts are saved in `stats.upgrades`; an id this version doesn't know is dropped. Stats fields are repaired in `Stats.fromJSON`: a save from an older economy (`economy` below `stats.ts` `ECONOMY`, now 2 for deliveries) keeps places visited and history, starts its money, deliveries and upgrades at 0, and drops XP, level and everything else this version no longer has. `Walker.fromJSON` puts an old save that was mid-ride (`travel`, `flight`) where the ride was headed, on `LONE_NODE`, and `saveFile.ts` moves the city there too. `OLD_KEYS` (the old weather and holiday stores) are removed on the next write. A save that can't be read or repaired is copied to `osmwalker.save.bad` (`BAD_SAVE_KEY`) before the new game overwrites it. `tests/unit/saveFile.test.ts` loads old saves through all of it. `tests/e2e/mock.ts` (`reopenWith`) edits the stored save, so it follows the save's shape.
- **Fresh map.** Past `MAX_CELLS` street cells in one city, `Game.freshMap` rebuilds the walker from its own save (`Walker.toJSON` then `fromJSON`) on an empty graph, and the cells around him reload, mostly from the cache. So a walker field the save leaves out is lost there too, not only on a reload.
- **Time.** Nothing runs while the game is closed or hidden: `Game.step` caps each step at `MAX_STEP_S`, so he goes on from where he was.
- **Sheet heights.** `src/ui/snap.ts` `TALL` is the tallest a dragged sheet gets; `src/ui/app.css` `.sheet` `max-height: 60%` must match it.
- **His look.** `src/core/look.ts` names each pop's motion (`rise`, `pop`); `src/ui/app.css` has a `.bubble` class and `@keyframes` of the same name for each.
- **Street cache.** `streets/idb.ts` prunes through an IndexedDB index on `Cached.t` (from `streets/source.ts`), so renaming that field or changing the store means a new database version with an upgrade step; a tab still running the older version blocks the upgrade; the new one then fetches streets from the network and closes its own connection when a newer version asks. `tests/unit/idb.test.ts` upgrades a version 1 database and covers both cases. A change to what a cell holds bumps `CACHE_VERSION` in `streets/source.ts`.
- **Tile decoding.** Only the streets worker decodes street tiles (`core/ofm.ts`, with `pbf` and `@mapbox/vector-tile`): `streets/source.ts` calls `fromPbf` on the bytes from `Api.streetTileBytes()`. Tiles drop the shared node where streets cross without bending, so `fromLayers` joins streets that cross on the ground (`joinCrossings`) and side streets that end on another (`joinJunctions`); bridges, tunnels and other layers stay apart. Page code (anything `src/ui/` imports, `net/api.ts` included) must not import the decoder, or it lands in startup JS; `tests/unit/api.test.ts` reads `net/api.ts` and fails if it calls `fromPbf`.
- **Lazy chunks.** `HelpSheet.tsx` imports `help.ts` with `import()`, to keep it out of startup JS. The service worker only caches what the page fetches, so `src/main.tsx` fetches the same chunks at idle once it is ready; a new lazy `import()` that must work offline needs a line there too.
- **Perf budgets.** `tests/perf/budgets.json` sets the limits `npm run verify` checks (transfer, first paint, ready, main thread, long tasks), checked against the median of three cold loads (`PERF_RUNS` changes the count), plus his page memory and DOM size after one game of 10 s riding about with the e2e fake services (`tests/e2e/mock.ts`; workers' memory isn't counted). `tests/perf/serve.mjs` must serve every file type the build has (`.mjs` for the map's worker). Startup JS size is not measured, but prefer choices that keep it small; a new dependency still shows in transfer.
- **Performance marks.** `osmwalker:map` (GameScreen, once the map scene runs) is awaited by `tests/e2e/screens.spec.ts`; `osmwalker:ready` (main.tsx) by `tests/perf/perf.mjs`. Renaming one breaks those tests.
- **Layout.** `tests/e2e/layout.spec.ts` opens every screen at 360 and 412 px and fails on overlap or sideways scroll. A new screen or sheet needs a step there. `npm run screens` (after a build) saves the shots in `screens/`; plain e2e runs skip them to save about 12 s.

## Tests

- `tests/unit/`: a file per module with logic worth testing alone (`walker.test.ts`, `help.test.ts`...); small or UI-only modules are covered through integration and e2e.
- `tests/integration/`: `game.test.ts` (game + walker + streets on fixture tiles; its harness is `tests/support/game.ts`) and `scene.test.ts` (scene + a fake map).
- `tests/e2e/`: Playwright on a Pixel 7 profile with mocked services (`mock.ts`). `live.spec.ts` plays the deployed site, by hand: `LIVE_URL=https://frostblooded.github.io/OSMWalker/ npx playwright test boot live`.
- **Where they run.** Only on the machine that pushes (`tools/verify.ts`). `npm run check` (lint, typecheck, and the unit/integration tests the change since master touches) is the quick one for while you work; `npm run verify` runs lint, typecheck, unit/integration tests and the build side by side, then e2e and perf side by side (perf mostly waits on a throttled page), and after a verified commit a change to tests only reruns those tests. Both remember the git tree that passed (`.git/verified/`, `.git/checked/`). `npm ci` points git at `.githooks/`, whose pre-push hook needs a check for a branch and a verify for `master`, and runs it when the pushed code is what is on disk. `npm run e2e:failed` reruns only the e2e tests that failed. `tools/chromium.ts` picks the browser for e2e and perf: `PW_CHROMIUM`, else the cloud sessions' headless Chromium, else Playwright's own. GitHub Actions (`web.yml`) only builds and deploys `master`.
