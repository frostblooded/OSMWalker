# Architecture map

Where things live, and the links between files that no import shows. Every
source file opens with a comment saying what it does; read that before the
code.

## Layers

Imports only point down this list (`src/sw/` imports nothing).

| Layer | Folder | What it holds |
| --- | --- | --- |
| Screens | `src/ui/` | Preact screens and sheets. `kit.tsx` + `app.css` are the UI kit (see `docs/ui-guidelines.md`). `help.ts` fills Help text with numbers from `src/core` (and `snap.ts`); `HelpSheet.tsx` loads it as its own chunk, off the startup path, and the text when Help first opens. |
| App | `src/app/` | `loop.ts` ticks the game while the page is visible; `idle.ts` yields and waits for idle time. |
| Map | `src/map/` | `scene.ts` decides what the map shows and where the camera points. `mapView.ts` is the only file that talks to MapLibre. |
| Game | `src/game/` | `game.ts` runs a city: walker, streets, rewards and saves. `saveFile.ts` saves and settings, `hud.ts` what the screens show. |
| Streets | `src/streets/` | The Web Worker that fetches, decodes and caches street tiles (`source.ts`), and `loader.ts`, which picks which tiles to load next. |
| Network | `src/net/api.ts` | The game's outside services: OpenFreeMap street tiles, Overpass, Photon and Nominatim search, and the city outline. The map style and map tiles are fetched by `src/map/mapView.ts` and MapLibre itself. |
| Core | `src/core/` | Pure logic with no DOM and no network: the walker (`walker.ts`), route (A*), the cards the player picks from (`cards.ts`), the upgrade ladder and what each upgrade lets him do (`upgrades.ts`), random spots and weighted dice (`goals.ts`), what each kind of place gives (`places.ts`), his money, XP, level, upgrades and places visited (`stats.ts`), history and his trail, his look on the map (`look.ts`), the debug log and problems, money in cents, a seedable RNG, and the street graph and tile decoding. |
| Offline | `src/sw/` | The service worker and its cache rules, built on its own. |

## Hidden links

- **Help text.** `public/data/help.txt` holds `{PLACEHOLDERS}`, and `src/ui/help.ts` fills them from core constants (the kinds of place come from `places.ts` `KINDS`). `vite.config.ts` hashes the file into `__HELP_VERSION__`, which goes in its address (`HelpSheet.tsx` `HELP_URL`), so a deploy that changes Help gives it a new address. The service worker serves a `data/` file with `?v=` cache-first and deletes its older versions when it stores a new one (`src/sw/strategy.ts` `replaced`). `tests/unit/help.test.ts` fails on a missing or unused value, a rewarding kind of place not named, or a screen button with no page.
- **Cards and rewards.** `places.ts` sorts the tiles' POI classes (`core/ofm.ts`) into work, sight and green; a class in none of them gives nothing and is never dealt (`cards.ts` `deal`). A card's reward is fixed when it is dealt (`rewardOf`, from the walk in `ROUTE_FACTOR` times the straight line at `WALK_MPS`) and paid on arrival (`Game.onArrived`, from `Choice.going`). With no goal the walker asks `events.idle`: the game deals cards and he waits for `Game.pick`; with nothing to deal he heads for a random spot. The map's numbered pins (`MapPort.setOffer`) follow the card order in `PickSheet.tsx`. A place he reaches without a step (he already stood as near as the streets go) counts as a skip, not a visit, so it can't pay over and over (`Walker.arrive`).
- **Upgrades and the economy.** `upgrades.ts` `LADDER` holds each upgrade's level, price and sellers; `powers()` turns what he owns into what `deal` may offer (4th card, reach, guide, parcel, metro, train cards) and his speed (`Game.equip`). A card's `slot` says what happens on arrival in `Game.onArrived`: a shop buys (`Stats.buy`), a parcel goes on to `to`, the metro jumps him (`Walker.startAt`), the train waits for a city (`Choice.train`, then `Game.travel`). Help's ladder list and numbers come from `upgrades.ts` (`help.ts` `ladder`). Any change to rewards, prices, levels or card distances goes through `npm run sim` (`tests/support/economy.ts`, the real `deal`, `rewardOf` and `Stats` in a made-up city), and `tests/unit/economy.test.ts` keeps the targets.
- **Saves.** Changing a saved field means a repair step on the way in from `src/game/saveFile.ts`, because players keep old saves. The cards (`choice`, with a parcel's or metro card's `to` and the `train` wait) are saved too, so a reload doesn't deal new ones; a save without them starts with none (`Choice.fromJSON`). Upgrades are saved in `stats.upgrades`; an id this version doesn't know is dropped. Stats fields are repaired in `Stats.fromJSON`: a save from before the base loop (no `economy`, `stats.ts` `ECONOMY`) keeps XP, level, places visited and history, starts its money at 0, and drops everything this version no longer has. `Walker.fromJSON` puts an old save that was mid-ride (`travel`, `flight`) where the ride was headed, on `LONE_NODE`, and `saveFile.ts` moves the city there too. `OLD_KEYS` (the old weather and holiday stores) are removed on the next write. A save that can't be read or repaired is copied to `osmwalker.save.bad` (`BAD_SAVE_KEY`) before the new game overwrites it. `tests/unit/saveFile.test.ts` loads old saves through all of it. `tests/e2e/mock.ts` (`reopenWith`) edits the stored save, so it follows the save's shape.
- **Fresh map.** Past `MAX_CELLS` street cells in one city, `Game.freshMap` rebuilds the walker from its own save (`Walker.toJSON` then `fromJSON`) on an empty graph, and the cells around him reload, mostly from the cache. So a walker field the save leaves out is lost there too, not only on a reload.
- **Time.** Nothing runs while the game is closed or hidden: `Game.step` caps each step at `MAX_STEP_S`, so he goes on from where he was.
- **Sheet heights.** `src/ui/snap.ts` `TALL` is the tallest a dragged sheet gets; `src/ui/app.css` `.sheet` `max-height: 60%` must match it.
- **His look.** `src/core/look.ts` names each pop's motion (`rise`, `pop`); `src/ui/app.css` has a `.bubble` class and `@keyframes` of the same name for each.
- **Street cache.** `streets/idb.ts` prunes through an IndexedDB index on `Cached.t` (from `streets/source.ts`), so renaming that field or changing the store means a new database version with an upgrade step; a tab still running the older version blocks the upgrade; the new one then fetches streets from the network and closes its own connection when a newer version asks. `tests/unit/idb.test.ts` upgrades a version 1 database and covers both cases. A change to what a cell holds bumps `CACHE_VERSION` in `streets/source.ts`.
- **Tile decoding.** Only the streets worker decodes street tiles (`core/ofm.ts`, with `pbf` and `@mapbox/vector-tile`): `streets/source.ts` calls `fromPbf` on the bytes from `Api.streetTileBytes()`. Page code (anything `src/ui/` imports, `net/api.ts` included) must not import the decoder, or it lands in startup JS; `tests/unit/api.test.ts` reads `net/api.ts` and fails if it calls `fromPbf`.
- **Lazy chunks.** `HelpSheet.tsx` imports `help.ts` with `import()`, to keep it out of startup JS. The service worker only caches what the page fetches, so `src/main.tsx` fetches the same chunks at idle once it is ready; a new lazy `import()` that must work offline needs a line there too.
- **Perf budgets.** `tests/perf/budgets.json` sets the limits `npm run verify` checks (transfer, first paint, ready, main thread, long tasks), checked against the median of three cold loads (`PERF_RUNS` changes the count), plus his page memory and DOM size after one game of 10 s walking with the e2e fake services (`tests/e2e/mock.ts`; workers' memory isn't counted). `tests/perf/serve.mjs` must serve every file type the build has (`.mjs` for the map's worker). Startup JS size is not measured, but prefer choices that keep it small; a new dependency still shows in transfer.
- **Performance marks.** `osmwalker:map` (GameScreen, once the map scene runs) is awaited by `tests/e2e/screens.spec.ts`; `osmwalker:ready` (main.tsx) by `tests/perf/perf.mjs`. Renaming one breaks those tests.
- **Layout.** `tests/e2e/layout.spec.ts` opens every screen at 360 and 412 px and fails on overlap or sideways scroll. A new screen or sheet needs a step there. `npm run verify` leaves the shots in `screens/`.

## Tests

- `tests/unit/`: a file per module with logic worth testing alone (`walker.test.ts`, `help.test.ts`...); small or UI-only modules are covered through integration and e2e.
- `tests/integration/`: `game.test.ts` (game + walker + streets on fixture tiles; its harness is `tests/support/game.ts`) and `scene.test.ts` (scene + a fake map).
- `tests/e2e/`: Playwright on a Pixel 7 profile with mocked services (`mock.ts`). `live.spec.ts` plays the deployed site, by hand: `LIVE_URL=https://frostblooded.github.io/OSMWalker/ npx playwright test boot live`.
- **Where they run.** Only on the machine that pushes (`tools/verify.ts`). `npm run check` (lint, typecheck, and the unit/integration tests the change since master touches) is the quick one for while you work; `npm run verify` runs lint, typecheck, unit/integration tests and the build side by side, then e2e, then perf, and after a verified commit a change to tests only reruns those tests. Both remember the git tree that passed (`.git/verified/`, `.git/checked/`). `npm ci` points git at `.githooks/`, whose pre-push hook needs a check for a branch and a verify for `master`, and runs it when the pushed code is what is on disk. `npm run e2e:failed` reruns only the e2e tests that failed. GitHub Actions (`web.yml`) only builds and deploys `master`.
